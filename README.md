## 什么是 Loom

**Loom** 是一个**开箱即用的 AI 高保真 UI 原型平台**。

你把需求——一句话、一个 Markdown 文件、一份 Word 文档，或者一份 PDF PRD——丢进来，Loom 会调用大模型，把需求**织**成一个**自包含、可交互、可直接在浏览器打开**的 HTML 原型。

> **Loom** 意为「织布机」。它把一缕一缕的需求线，织成一整块可交互的原型布。

和传统原型工具不同，Loom 的全部代码就是**一个 HTML 文件**：

- 不需要 `npm install`
- 不需要构建
- 不需要后端
- 不需要账号注册

打开就能用，导出就能跑。**你手里拿到的不是一个生成结果，而是一个生成工具。**

### 为什么做 Loom

市面上的 AI 原型工具大致分两类：

- **闭源 SaaS 类**（如 v0、Lovable、Bolt）：能力强、生态好，但绑定账号、绑定服务商、数据不可控。
- **代码生成类**（如 Cursor、Claude Code）：灵活，但需要开发者环境，产品/设计同学用不起来。

Loom 想填补的是一条中间路线——**产品经理、设计师、独立开发者打开浏览器就能用，数据完全留在本地，生成结果是可交付的单文件**。

### 核心理念

| 理念 | 具体表现 |
|------|----------|
| **单文件** | 零构建、零部署，一个 `index.html` 就是全部 |
| **全前端** | 无中间服务器、无遥测、无数据上报 |
| **自包含产物** | 生成的原型只用内联 CSS/JS，双击即运行 |
| **多模型** | 不绑定任何服务商，本地 OpenCode / 8 家云端 / 自定义端点皆可 |
| **防御式** | 所有响应、文件、结构都做多层兜底，出错也有明确提示 |

## 核心特性

### 📥 多格式需求导入

| 格式 | 支持 | 实现方式 |
|------|:----:|----------|
| 纯文字 | ✅ | 直接在左侧文本域撰写 |
| Markdown (`.md` / `.markdown`) | ✅ | `FileReader.readAsText` |
| 纯文本 (`.txt`) | ✅ | `FileReader.readAsText` |
| Word (`.docx`) | ✅ | 原生 ZIP 解析 + `DecompressionStream` 解压 + XML 提取 |
| PDF (`.pdf`) | ✅ | 按需加载 pdf.js，逐页提取文字 |

- 拖拽或点击即可导入
- 导入后自动显示前 800 字符预览
- 自动切换到「文件」Tab，避免误用旧文本
- 显示文件大小与解析字符数

> 旧版 `.doc` 不支持，会提示另存为 `.docx`。

### 📱 三种目标设备

生成时明确告诉模型目标形态，Loom 会把对应的设计规范注入 System Prompt：

| 设备 | 视口 | 关键规范 |
|------|------|----------|
| 📱 手机 | 393 × 852 | 单列为主 / 底部 tab bar / 44px 最小触控区 / 正文 14-15px |
| 💻 网站 | 1440 × 900 | 侧边栏 + 多列主区 / hover 状态 / 正文 14-16px |
| 🖥️ 平板 | 820 × 1180 | 可折叠侧栏 / 双列 / 触控笔友好 / 正文 15-16px |

预览区**自动跟随目标设备**，无需手动切换。

### 🔌 多模型接入

**OpenCode 本地直连**（推荐，可免费使用）
- 从本地 OpenCode 服务拉取全部模型
- 可按「免费 / 全部」浏览挑选
- 留空则使用 OpenCode 默认模型
- 支持服务端密码认证

**云端服务商**（8 家 + 自定义）

| 服务商 | 默认模型 | 免费额度 |
|--------|----------|----------|
| Anthropic | `claude-opus-4-5-20251101` | 需付费 |
| OpenAI | `gpt-4o-mini` | 需付费 |
| Groq | `llama-3.3-70b-versatile` | ✅ 30 RPM / 1K RPD |
| Cerebras | `llama3.3-70b` | ✅ 30 RPM / 14.4K RPD |
| OpenRouter | `llama-3.3-70b-instruct:free` | ✅ 20 RPM / 50 RPD |
| SambaNova | `DeepSeek-V3.1` | ✅ 60 RPM / 12K RPD |
| Gemini | `gemini-2.5-flash` | ✅ 较宽松 |
| Mistral | `mistral-small-latest` | ✅ 需手机验证 |
| 自定义 | 手动填写 | 视端点而定 |

**配置集中管理**：服务商、地址、Key、模型全部集中在「模型配置中心」弹窗，不占用左侧工作区。

### 🎨 生成过程可控

**Skills 多选**（注入 System Prompt 作为约束）
- 高保真原型 / 设计系统 / 反俗套 / 交互逻辑 / 响应式 / 数据可视化

**设计方向**（影响视觉风格）
- 极简商务 / 暖色亲和 / 科技深色 / 高对比数据 / 编辑杂志 / 柔和莫兰迪

**生成轨迹**（时间线形式）
- 展示每一步耗时：准备会话 → 发送请求 → 响应返回 → 解析完成
- 绿色表示成功，红色表示错误，蓝色表示信息
- 面板可折叠，出错时可快速定位

### 💬 迭代对话

生成后不推倒重来。

- 在右栏描述修改意见（如「按钮太小」「增加一个确认弹窗」「换深色主题」）
- Loom 把**当前 HTML + 修改意见**打包给模型做增量修改
- 生成新版本覆盖预览，旧版本不保留（可在轨迹里看到迭代次数）

> 迭代时会复用同一个 OpenCode 会话，保留上下文；首次生成会新建会话。

### 🔍 实时流式预览

LLM 流式返回，Loom 一边接收一边渲染：

- 每 500ms 节流更新预览
- 骨架先出，内容渐填
- 右侧对话区实时显示文件大小

### 🖥 全屏专注

- 点工具栏全屏按钮，或按 `F` 键
- 全屏时工具栏保留，可随时切换设备、刷新或退出
- 轨迹面板在全屏时自动隐藏，回归专注

### 📤 三种导出格式

| 格式 | 实现方式 | 适用场景 |
|------|----------|----------|
| **HTML** | 直接下载自包含单文件 | 双击打开、内嵌演示、发给客户 |
| **Word** | 包装为 `.doc`，注入 mso 兼容头 | 需要作为设计文档交付 |
| **PDF** | 隐藏 iframe 调起浏览器打印 | PDF 归档或打印审阅 |

> 导出的 HTML 无任何外部依赖，可直接部署到 GitHub Pages / Vercel / Nginx。

### 🛡 安全与隔离

- 生成的 HTML 在 `sandbox="allow-scripts"` 的 iframe 中运行
- 预览环境无法访问父页面 DOM、Cookie、localStorage
- 生成的 HTML 被约束为完全自包含（无 CDN、无外部字体、无外部图片）

## 快速开始

### 环境要求

- 现代浏览器（Chrome / Edge / Safari / Firefox 最新版）
- 无需 Node.js、无需后端服务
- PDF 导入需联网（按需加载 pdf.js 解析库）

### 三步上手

**① 获取 Loom**

```bash
git clone https://github.com/your-org/loom.git
cd loom
```
或直接把 index.html 保存到本地任意目录。
② 打开
```bash
# 推荐：用本地静态服务器打开（避免 CORS 和 iframe 限制）
npx serve .

# 或使用 VS Code 的 Live Server 插件
# 或 Python 内置服务器
python3 -m http.server 3000
```

然后访问 http://localhost:3000。

为什么不用 file:// 直接打开？
file:// 下浏览器对 fetch 的 CORS 限制更严，某些模型服务商的预检请求会因 Origin 为 null 而失败。用本地静态服务器最稳妥。

③ 配置模型

点右上角「模型配置」，选择服务商，填写对应配置，点「测试连接」确认连通。

支持的模型
方式一：OpenCode 本地直连（推荐 · 免费）
① 启动 OpenCode 服务

```bash
# 如果通过 http://localhost:3000 打开 Loom
opencode serve --port 4096 --cors http://localhost:3000

# 如果通过 file:// 打开 Loom
opencode serve --port 4096 --cors null
```

② 在 Loom 中配置

服务商选 OpenCode 本地直连

地址填 http://localhost:4096

点「测试连接」

点「浏览 ▾」挑选免费模型（留空则使用 OpenCode 默认模型）

③ 免费模型识别规则

Loom 会尝试 /api/model、/models、/providers、/config/providers 四个端点，按以下规则识别免费模型：

模型名含 free（不区分大小写）→ 免费

providerID === 'opencode' 且 cost 缺失 → 免费（Zen 大部分模型）

providerID === 'opencode' 且 cost.input/output/cache 全为 0 → 免费

免费模型在浏览面板中带绿色 FREE 徽章。

方式二：云端服务商
Anthropic
```bash
服务商：Anthropic
模型：claude-opus-4-5-20251101
API Key：sk-ant-...

```

速率限制应对
免费层通常不适合单次生成超过 20KB 的内容。如果遇到 429：

降低 max_tokens（代码中默认 24000，可调小）

切换到每日额度更高的 Cerebras / SambaNova

把复杂原型拆成「先生成骨架，再迭代补全交互」两步

关键技术决策

决策	理由
单 HTML 文件	零构建、零部署，用户拿到就能用
全前端	无中间服务器，数据不出本地，无遥测
sandbox iframe	生成的 HTML 是不可信内容，必须隔离
原生 ZIP 解析	避免引入 JSZip 等外部依赖，保持单文件
pdf.js 按需加载	PDF 是低频功能，不值得为它打包整个库
防御式解析	不同模型/版本的响应结构差异大，必须多层兜底
流式渲染	用户等待时间感知更短，体验更好

System Prompt 设计

Loom 的 System Prompt 由三部分拼接：

基础规范（BASE_SYSTEM）：输出格式、自包含约束、质量基线

设备约束（DEVICE_PRESETS）：目标视口、布局、字号、圆角

Skills（用户勾选）：每个 Skill 一段约束

三者叠加后再发给模型，保证输出既符合通用规范，又针对目标设备优化。

免费模型识别
OpenCode 的免费模型识别采用自适应策略：

成本驱动：如果 provider 暴露了定价信息，cost.input === 0 && cost.output === 0 即为免费

名称驱动：如果 provider 不暴露定价（如 OpenCode Zen），则根据模型名是否含 free 判断

Loom 两条规则都实现了，并优先尝试成本驱动，失败时降级到名称驱动。

数据与隐私


API Key：仅保存在浏览器 localStorage，不发送到任何第三方服务器

需求内容：仅发送到你配置的模型服务商

生成的 HTML：不上传、不留存，只在本地内存和 iframe.srcdoc 中存在

无遥测：Loom 不含任何统计脚本

无 Cookie：不使用 Cookie 或任何跨站追踪技术

如果你在企业环境使用，建议：

使用本地 OpenCode 直连，数据完全不出内网

定期清理浏览器 localStorage 中的 API Key

不要在公共电脑上保存 API Key
